## Мета роботи

Вивчити та закріпити на практиці можливості системи керування версіями, одержати практичний досвід у використанні Git та GitHub.

## Теоретичні відомості

**Система керування версіями** (SCM, VCS) – програма, яка зберігає історію змін файлів проєкту: хто, коли і що змінив. Завдяки їй можна повернутись до будь-якої попередньої версії і спокійно працювати над одним проєктом командою.

Системи керування версіями бувають двох типів:

- **централізовані** (Subversion, Team Foundation Server) – уся історія лежить на одному сервері, без мережі не закомітиш;
- **розподілені** (Git, Mercurial) – кожен розробник має повну копію репозиторію з історією і може працювати офлайн.

**Git** – розподілена система керування версіями. **GitHub** – вебсервіс, де зберігаються Git-репозиторії і де зручно працювати командою: Pull Request, рецензування коду, обговорення.

Основні поняття:

- **репозиторій** – сховище файлів проєкту разом з історією змін;
- **гілка (branch)** – окрема лінія розробки; основна гілка зазвичай `main` (раніше `master`, на сленгу – trunk);
- **коміт (commit)** – зафіксований знімок змін;
- **Pull Request** – запит на злиття однієї гілки в іншу з можливістю рецензування;
- **review / approve** – перевірка змін іншим учасником і їх схвалення;
- **merge** – злиття змін з гілки в основну.

Основні команди Git:

| Команда | Призначення |
|---|---|
| `git init` | створити новий репозиторій у поточній папці |
| `git clone <url>` | скопіювати віддалений репозиторій |
| `git add` | додати зміни в індекс (staging area) |
| `git status` | показати стан файлів |
| `git commit -m "..."` | зафіксувати зміни з індексу |
| `git push` | відправити коміти у віддалений репозиторій |
| `git fetch` | забрати зміни з віддаленого репозиторію без злиття |
| `git pull` | `fetch` + `merge`: забрати й одразу злити зміни |
